Semantică Statică, AST & Proiectul M+-

Ghid teoretic complet al etapei de analiză contextuală: construcția Arborelui Sintactic Abstract (AST), gestionarea Tabelei de Simboluri pe domenii de vizibilitate, verificarea strictă a tipurilor în limbajul didactic M+-, generarea codului intermediar 3AC, analiza de flux și manualul oficial EBNF.

1 Limitările Gramaticilor Independente de Context (CFG)

Gramaticile CFG pot descrie doar structura sintactică ierarhică (imbricarea parantezelor, blocurilor etc.), dar sunt incapabile matematic să captureze dependențele contextuale ale limbajelor reale:

Constrângeri Semantice Ce NU Pot Fi Verificate de un Parser Sintactic:
  • O variabilă trebuie să fie declarată înainte de a fi utilizată.
  • O variabilă nu poate fi redeclarată în același domeniu de vizibilitate (același bloc).
  • Tipurile de date ale operanzilor unei operații trebuie să fie compatibile.
  • Condiția dintr-o buclă WHILE expr DO trebuie să se evalueze strict la tipul BOOL.
  • La apelul unei funcții, numărul și tipurile argumentelor trebuie să corespundă semnăturii declarate.

2 Gramatici cu Atribute: Atribute Sintetizate (S) vs. Moștenite (L)

Formalismul Definițiilor Dirijate de Sintaxă (Syntax-Directed Definitions — SDD) atașează fiecărui simbol gramatical o mulțime de atribute și fiecărei producții o mulțime de reguli semantice:

Atribute Sintetizate (S-Attributed)

Valoarea atributului nodului părinte A depinde exclusiv de fiii săi:

E → E1 + T  ⇒  E.val = E1.val + T.val
  • Evaluate natural de jos în sus (bottom-up).
  • 100% compatibile cu parserele LR / Bison (evaluate direct pe stivă prin $$ = $1 + $3).
Atribute Moștenite (L-Attributed)

Valoarea atributului nodului Xi depinde de părinte sau de frații din stânga:

D → T L  ⇒  L.in_type = T.type
  • Evaluate de sus în jos (top-down, de la stânga la dreapta).
  • Compatibile cu parserele predictive LL(1) și coborârea recursivă.
Grafuri de Dependență & Sortare Topologică: Pentru calculul atributelor, compilatorul construiește un graf orientat al dependențelor între instanțele de atribute. Dacă graful este aciclic (DAG), orice sortare topologică furnizează o ordine validă de evaluare. Dacă graful are cicluri, gramatica este circulară și invalidă!

3 Arborele Sintactic Abstract (AST) vs. Parse Tree Concret

Diferența dintre Arborele Concret (Parse Tree) și Arborele Abstract (AST) este un reper critic de arhitectură:

Criteriu Parse Tree Concret Arbore Sintactic Abstract (AST)
Noduri Interioare Conține neterminalele intermediare de precedență (E, E', T, T', F) Conține exclusiv operatorii semantici (+, *, IF, ASSIGN)
Punctuație & Paranteze Păstrează toate parantezele '(', ')', virgulele și ';' Elimină complet parantezele (ierarhia este stocată în arce)
Memorie & Eficiență Voluminos, dependent de gramatica specifică folosită Compact, dens semantic, optim pentru optimizări și cod 3AC
Structura Nodului C în Proiectul M+- (ast.h): 
typedef struct Node {
    NodeType type;         // PROGRAM_NODE, IF_NODE, WHILE_NODE, ASSIGN_NODE etc.
    char *name;            // Nume identificator sau operator
    int intVal;            // Valoare dacă e constantă întreagă
    double realVal;        // Valoare dacă e constantă reală
    int boolVal;           // Valoare booleană (0 sau 1)
    struct Node *child[4]; // Fiii nodului (ex: if are condiție, ramură then, ramură else)
    struct Node *next;     // Pentru liste înlănțuite de instrucțiuni sau declarații
} Node;

4 Tabela de Simboluri pe Domenii de Vizibilitate (Scoped Symbol Table)

Deoarece blocurile imbricate ({ ... }) și corpurile funcțiilor pot declara variabile locale cu același nume ca variabilele din blocurile exterioare (Name Shadowing), tabela de simboluri este organizată ca o stivă de tabele locale:

enter_scope():

Apelat la intrarea într-un nou bloc sau funcție; împinge pe stivă o nouă tabelă de simboluri goală, având indicator către tabela părinte.

exit_scope():

Apelat la ieșirea din bloc sau funcție; eliberează toate variabilele locale declarate în acel bloc.

lookup(name):

Caută identificatorul începând din tabela curentă (cea mai profundă); dacă nu îl găsește, urcă pe lanțul părinților până la tabela globală. Dacă nu este găsit nici în tabela globală, emite "Eroare: variabilă nedeclarată".

5 Sistemul de Tipuri în Limbajul Didactic M+-

Limbajul M+- conține 3 tipuri de bază: INT, REAL și BOOL.

Operatori Aritmetici (+, -, *, /)

INT + INT → INT
INT + REAL → REAL (coerciție implicită la REAL)
REAL + REAL → REAL

Operatori Logici (&&, ||, not)

Operanzii trebuie să fie strict BOOL!
Dacă un operand este INT, se raportează eroare de tip (fără conversie stil C)!

Capcană Clasică de Examen (WHILE / IF): În M+-, scrierea WHILE 1 DO este INVALIDĂ SEMANTIC, deoarece 1 este de tip INT, nu BOOL! O buclă corectă trebuie să folosească o expresie de comparație: WHILE 1 = 1 DO sau WHILE true DO.

6 Cod cu Trei Adrese (3AC), Dataflow & Back-End

În codul 3AC, fiecare instrucțiune are cel mult un operator în partea dreaptă: x = y op z. Expresiile complexe sunt descompuse prin variabile temporare t1, t2, ....

Traducerea Instrucțiunii: WHILE (a < b) DO a := a + 1; 
L_start:
    t1 = a < b
    ifFalse t1 goto L_end
    a = a + 1
    goto L_start
L_end:
Analiza Fluxului de Date (Dataflow Analysis, cf. sld1.pdf slide 19):
  • DEF: Variabile cărora li se atribuie o valoare în bloc.
  • USE: Variabile a căror valoare este citită/folosită în bloc.
  • GEN: Definiții generate în bloc care ajung la ieșire.
  • KILL: Definiții din program anulate prin reatribuiri locale.
Cele 4 Etape ale Sintezei Back-End (Virtual to Physical Binding, slide 22):
  1. Instruction Selection: Maparea opcoadelor generice pe instrucțiuni native (ex: lea pe x86).
  2. Register Allocation (Chaitin): Maparea temporarilor pe N regiștri fizici prin colorarea grafului de interferență (cu spilling pe stivă).
  3. Instruction Scheduling: Reordonarea instrucțiunilor pentru prevenirea pauzelor de pipeline.
  4. Assembly Emission: Emiterea fișierului text de asamblare (.s).

7 Manualul Oficial EBNF al Limbajului M+- (Cd_ProjMPlusMinus.pdf)

Extrasul complet al regulilor de producție din caietul oficial de proiect: 

prog -> block
block -> declarations program_body
declarations -> declaration SEMICOLON declarations | /* epsilon */
declaration -> var_declaration | fun_declaration
var_declaration -> VAR ID array_dimensions COLON type
type -> INT | REAL | BOOL
array_dimensions -> SLPAR expr SRPAR array_dimensions | /* epsilon */
fun_declaration -> FUN ID param_list COLON type CLPAR fun_block CRPAR
fun_block -> declarations fun_body
param_list -> LPAR parameters RPAR
parameters -> basic_declaration more_parameters | /* epsilon */
more_parameters -> COMMA basic_declaration more_parameters | /* epsilon */
basic_declaration -> ID basic_array_dimensions COLON type
basic_array_dimensions -> SLPAR SRPAR basic_array_dimensions | /* epsilon */
program_body -> BEGIN prog_stmts END
fun_body -> BEGIN prog_stmts RETURN expr SEMICOLON END
prog_stmts -> prog_stmt SEMICOLON prog_stmts | /* epsilon */
prog_stmt -> IF expr THEN prog_stmt ELSE prog_stmt
           | WHILE expr DO prog_stmt
           | READ identifier
           | identifier ASSIGN expr
           | PRINT expr
           | CLPAR block CRPAR
identifier -> ID array_dimensions
expr -> expr OR bint_term | bint_term
bint_term -> bint_term AND bint_factor | bint_factor
bint_factor -> NOT bint_factor | int_expr compare_op int_expr | int_expr
compare_op -> EQUAL | LT | GT | LE | GE
int_expr -> int_expr addop int_term | int_term
addop -> ADD | SUB
int_term -> int_term mulop int_factor | int_factor
mulop -> MUL | DIV
int_factor -> LPAR expr RPAR
            | SIZE LPAR ID basic_array_dimensions RPAR
            | DIM LPAR ID basic_array_dimensions RPAR
            | FLOAT LPAR expr RPAR
            | FLOOR LPAR expr RPAR
            | CEIL LPAR expr RPAR
            | ID modifier_list
            | IVAL | RVAL | BVAL | SUB int_factor
modifier_list -> LPAR arguments RPAR | array_dimensions
arguments -> expr more_arguments | /* epsilon */
more_arguments -> COMMA expr more_arguments | /* epsilon */
