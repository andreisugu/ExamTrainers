Analiză Sintactică Top-Down & Gramatici LL(1)

Studiul aprofundat al analizei sintactice predictive descendente: transformări canonice de gramatici, calculul riguros al mulțimilor FIRST și FOLLOW, construirea tabelului matricial M[A, a] și implementarea manuală prin coborâre recursivă în C++.

1 Gramatici Independente de Context (CFG) & Ambiguitate

O Gramatică Independentă de Context (Context-Free Grammar — CFG) este un 4-tuplu formal:
G = (VN, VT, S, P)

  • VN: Mulțimea neterminalelor (simboluri sintactice compuse, ex: E, T, F).
  • VT: Mulțimea terminalelor (tokenii furnizați de scanner, ex: id, +, *, ().
  • S ∈ VN: Simbolul de start (rădăcina gramaticii).
  • P: Producțiile gramaticale de forma A → α, unde A ∈ VN și α ∈ (VN ∪ VT)*.
Ambiguitatea Gramaticilor (Definiție Oficială de Examen):

O gramatică este ambiguă dacă există cel puțin un cuvânt din limbaj pentru care se pot construi doi sau mai mulți arbori de derivare distincți (sau echivalent, două derivări canonice la stânga distincte).

⇒ Exemple celebre: Expresiile aritmetice fără ierarhie de precedență (E → E + E | E * E | id) și problema Dangling-Else în instrucțiunea if E then S else S.

2 Algoritmii Formale de Calcul pentru FIRST & FOLLOW

Calculul acestor două mulțimi este esențial pentru rezolvarea a cel puțin 30% din grilele de la examen.

{/* FIRST Box */}
A. Calculul Mulțimii FIRST(α):

FIRST(α) este mulțimea tuturor terminalilor cu care poate începe un șir derivat din α. Dacă α ⇒* ε, atunci ε ∈ FIRST(α).

  1. Dacă X este terminal, atunci FIRST(X) = { X }.
  2. Dacă X → ε este o producție, se adaugă ε în FIRST(X).
  3. Dacă X → Y1 Y2 ... Yk: se adaugă FIRST(Y1) \ {ε}. Dacă Y1 ⇒* ε, se adaugă și FIRST(Y2) \ {ε} și așa mai departe până la primul neterminal care nu poate deriva ε.
{/* FOLLOW Box */}
B. Calculul Mulțimii FOLLOW(A):

FOLLOW(A) este mulțimea tuturor terminalilor care pot apărea imediat la dreapta lui A într-o formă sentențială derivabilă.

🚨 PORUNCA NR. 1 DE EXAMEN: Simbolul ε NU APARE NICIODATĂ într-o mulțime FOLLOW!
  1. Pasul 1 (Simbolul de start): Se adaugă marcajul de sfârșit de fișier $ în FOLLOW(S).
  2. Pasul 2 (Regula de succesiune): Dacă există o producție de forma A → α B β, atunci toate elementele din FIRST(β) \ {ε} se adaugă în FOLLOW(B).
  3. Pasul 3 (Regula de propagare din coadă): Dacă există o producție de forma A → α B SAU A → α B β unde ε ∈ FIRST(β), atunci toate elementele din FOLLOW(A) se adaugă în FOLLOW(B)!

3 Construcția Tabelului de Parsare LL(1) M[A, a]

Tabelul M[A, a] ghidează parserul predictiv: pentru neterminalul A din vârful stivei și tokenul a din fluxul de intrare, indică regula de producție care trebuie aplicată.

Algoritmul de Populare a Tabelului:

Pentru fiecare producție A → α a gramaticii:

  1. Pentru fiecare terminal a ∈ FIRST(α): se pune A → α în M[A, a].
  2. Dacă ε ∈ FIRST(α): pentru fiecare b ∈ FOLLOW(A) (inclusiv $), se pune A → α în M[A, b].
Teorema Fundamentală LL(1): O gramatică este strict LL(1) dacă și numai dacă fiecare celulă M[A, a] conține cel mult o singură producție (nu există conflicte / intrări multiple în matrice).

4 Transformări Algebrice: Eliminare Recursivitate & Factorizare

Dacă o gramatică nu este LL(1), ea poate fi adusă în clasa LL(1) prin două transformări:

1. Eliminarea Recursivității Directe la Stânga

O regulă A → A α | β blochează un parser top-down într-o buclă infinită!

A → β A'
A' → α A' | ε

Exemplu: E → E + T | T devine E → T E' și E' → + T E' | ε.

2. Factorizarea la Stânga (Left Factoring)

Dacă două alternative încep cu același prefix: A → α β1 | α β2, parserul nu poate decide determinist.

A → α A'
A' → β1 | β2

Exemplu: S → if E then S | if E then S else S se factorizează prin izolarea clauzei else S | ε.

5 Parsarea prin Coborâre Recursivă Manuală (Hand-Coded)

Conform suportului de curs lexer_parser.pdf, parserele LL pot fi scrise manual în C/C++ fără generatoare automate: 

Token lookahead;

void match(TokenType expected) {
    if (lookahead.type == expected) {
        lookahead = nextToken(); // avans determinist
    } else {
        syntaxError("Token neașteptat!");
    }
}

void E() {
    T();
    E_prime();
}

void E_prime() {
    if (lookahead.type == TOKEN_PLUS) {
        match(TOKEN_PLUS);
        T();
        E_prime();
    }
    // ramura epsilon: nu se consumă token
}
Recuperarea din Erori (Panic Mode pe FOLLOW): Dacă într-o procedură A() este detectat un token nevalid, parserul consumă tokeni din intrare până când întâlnește un simbol din mulțimea FOLLOW(A) (de exemplu ; sau )). În acel moment, procedura A() revine, iar funcția apelantă își poate continua execuția fără a întrerupe compilarea!

⚠️ Capcane Mortale de Examen la Analiză Top-Down LL(1)

  • • Regula ε în FOLLOW: Dacă găsești simbolul ε într-o variantă de răspuns pentru FOLLOW(X), o elimini instantaneu! FOLLOW conține exclusiv terminali și $.
  • • Uitarea marcajului $: Pentru simbolul de start S, $ ∈ FOLLOW(S) este pus din oficiu.
  • • Propagarea din coadă: La producția A → α B β, dacă β ⇒* ε, multor studenți le scapă adăugarea elementelor din FOLLOW(A) în FOLLOW(B)!
  • • Incompatibilitatea LL(1) cu recursivitatea la stânga: Orice gramatică recursivă la stânga (directă sau indirectă) este descalificată din oficiu de la clasa LL(1).
