Analiză Lexicală, Automate Finite & Flex

Ghid teoretic exhaustiv pentru recunoașterea vocabularului limbajelor de programare: conversia expresiilor regulate în NFA prin algoritmul lui Thompson, determinizarea Subset Construction, minimizarea DFA Hopcroft, funcționarea internă a scanerului Flex și diagramele de compilare în T.

1 Token, Lexem, Tipar & Valori Semantice

Analizorul lexical (Scanner) citește fluxul brut de caractere sursă, elimină spațiile albe și comentariile și grupează caracterele în unități atomice numite tokeni.

Token (Categorie) Simbol abstract reprezentând clasa lexicală:

ID, NUM, WHILE, ASSIGN

Lexem (Instanță) Secvența concretă de caractere din codul sursă:

"contor", "3.14", ":="

Tipar (Pattern) Expresia regulată descriptivă a categoriei:

[a-zA-Z_][a-zA-Z0-9_]*

Valoarea Semantică (yylval): Când analizorul sintactic (parserul) primește un token, el are nevoie de informația semantică exactă pentru a construi arborele AST (ex: valoarea numerică binară pentru un NUM sau adresa din tabela de simboluri pentru un ID):

⟨ID, "total"⟩  •  ⟨NUM, 42⟩  •  ⟨ASSIGN, ":="⟩  •  ⟨WHILE, —⟩

2 Automate Finite Nedeterministe (NFA) vs. Deterministe (DFA)

Un automat finit este definit matematic ca un 5-tuplu: M = (S, Σ, δ, s0, F), unde:

  • S: Mulțimea finită a stărilor automatului.
  • Σ: Alfabetul de intrare (mulțime finită de simboluri).
  • δ: Funcția de tranziție între stări.
  • s0 ∈ S: Starea inițială.
  • F ⊆ S: Mulțimea stărilor finale (de acceptare).
NFA (Nedeterminist)

Tranziția: δ: S × (Σ ∪ {ε}) → P(S)

  • Permite tranziții spontane ε (fără consum de caracter).
  • Dintr-o stare pot pleca mai multe arce cu același simbol.
  • Simplu de construit din RE (algoritmul lui Thompson).
  • Lent la execuție directă pe șir (necesită simulare de mulțimi).
DFA (Determinist)

Tranziția: δ: S × Σ → S

  • Fără tranziții ε.
  • Exact o singură stare următoare pentru orice pereche (stare, caracter).
  • Execuție ultra-rapidă Ο(n) prin simplă căutare în tabel matriceal.
  • Reprezintă forma finală compilată de generatoare precum Flex.

3 Algoritmul lui Thompson (Construcția Inductivă RE → NFA)

Algoritmul lui Ken Thompson descompune recursiv expresia regulată în sub-expresii atomice și asamblează un NFA echivalent.

Proprietățile Structurale Garantate ale NFA-ului lui Thompson:

1. Are exact o stare inițială (fără tranziții care intră în ea) și exact o stare finală (fără tranziții care pleacă din ea).

2. Din orice stare pleacă cel mult două tranziții ε.

3. Numărul total de stări al NFA-ului compus este de cel mult 2 × lungimea(RE).

1. Simbolul de Bază 'a':

(start) → [s_init] — a → ((s_final))

2. Concatenarea (r1 r2):

Starea finală a automatului N(r1) fuzionează cu starea inițială a lui N(r2).

3. Reuniunea / Alternanța (r1 | r2):

Se creează o nouă stare inițială cu ramificații ε către N(r1) și N(r2), iar ieșirile converg prin ε într-o nouă stare finală unică.

4. Închiderea Kleene (r*):

Nouă stare de start cu arc ε direct către noua stare finală (pentru cuvântul vid) și arc ε către N(r). Ieșirea din N(r) are arc de buclă ε înapoi către intrare și arc ε către noua stare finală.

4 Determinizarea prin Algoritmul Subset Construction

Determinizarea transformă un NFA cu tranziții ε într-un DFA echivalent, unde fiecare stare DFA corespunde unei mulțimi de stări NFA.

Cele Două Operații Fundamentale:

1. ε-closure(s): Mulțimea stărilor NFA accesibile din starea s urmând exclusiv tranziții ε (inclusiv starea s însăși).

2. move(T, a): Mulțimea stărilor NFA în care se poate ajunge din oricare stare s ∈ T consumând simbolul terminal a:
move(T, a) = ∪s ∈ T δ(s, a)

Studiu de Caz Clasic de Examen: RE = (a | b)* a b b

Starea inițială a DFA-ului este S0 = ε-closure(s0). La fiecare iterație, pentru fiecare simbol de intrare a ∈ Σ, se calculează:
U = ε-closure(move(S_curent, a))
Dacă U nu există încă în tabela DFA, se adaugă ca stare nouă. O stare DFA este stare finală dacă conține starea finală din NFA-ul original!

5 Minimizarea Hopcroft a Stărilor DFA

Un DFA determinizat poate conține stări redundante (echivalente). Algoritmul Hopcroft găsește DFA-ul minimal unic în timp Ο(n log n).

Pasul 1 (Partiția Inițială):

Se separă stările în două grupe disjuncte: stări finale (F) și stări nefinale (S \ F): P = {F, S \ F}.

Pasul 2 (Rafinarea prin Split):

Pentru fiecare grup G și fiecare simbol 'a', dacă tranzițiile pe 'a' din stările lui G aterizează în grupuri diferite, grupul G este divizat.

Pasul 3 (Punctul Fix):

Repetă pasul 2 până când nicio grupă nu mai poate fi divizată. Fiecare grupă rămasă devine o singură stare în DFA-ul minimizat.

6 Scanerul Flex & Regulile de Ambiguitate

Un fișier Flex (.l) are trei secțiuni delimitate de %%:

Structura Canonică a unui fișier Flex (.l): 
%{
/* 1. Secțiunea de Declarații C (include-uri, variabile globale) */
#include "parser.tab.h"
%}
%option noyywrap yylineno

%%
/* 2. Secțiunea Regulilor de Translatare (Tipar { Acțiune C }) */
"while"          { return WHILE; }
[a-zA-Z_][a-zA-Z0-9_]* { yylval.str = strdup(yytext); return ID; }
[0-9]+           { yylval.num = atoi(yytext); return INT_CONST; }
":="             { return ASSIGN; }
[ \t\r\n]+       { /* ignoră spațiile albe */ }
.                { fprintf(stderr, "Eroare lexicală: %s\n", yytext); }

%%
/* 3. Secțiunea Rutinelor Utilizator C */
int main() { yylex(); return 0; }
1. Longest Match (Maximal Munch)

Scanerul consumă întotdeauna cel mai lung prefix care se potrivește cu un tipar valid.

Exemplu: Pentru șirul while2, deși prefixul while se potrivește cu cuvântul cheie WHILE, Flex consumă întreg șirul de lungime 6 și returnează ID!

2. First Rule Wins (Prioritate)

Dacă două reguli potrivesc exact aceeași lungime de caractere, prima regulă declarată în fișier câștigă.

Regulă vitală: Cuvintele cheie (while, if) trebuie declarate înaintea tiparului generic de identificator ([a-z]+)!

7 Diagramele în T (Bratman, 1961) & Bootstrapping

Diagramele în T descriu formal relația dintre limbajul Sursă (S), limbajul Țintă (T) și limbajul de Implementare (I): 

+---------+---------+
| Sursa S | Tinta T |
+---------+---------+
          |    I    |
          +---------+
            (Impl)

Un compilator S → T scris în limbajul I

Compilarea Încrucișată (Cross-Compilation): Un compilator care rulează pe o mașină gazdă (Host, ex: x86) dar generează cod pentru o arhitectură țintă diferită (Target, ex: microcontroler ARM / RISC-V).

Procesul de Bootstrapping (Auto-Găzduire în 3 Pași):

  1. Se scrie un compilator minimal pentru un nucleu restrâns L0 într-un limbaj existent (ex: C sau Asamblor).
  2. Se scrie compilatorul complet pentru limbajul L în subsetul L0 și se compilează cu compilatorul din pasul 1.
  3. Se rescrie compilatorul complet pentru L chiar în limbajul L și se auto-compilează. Din acel moment, compilatorul devine complet self-hosting!

⚠️ Capcane Frecvente de Examen la Analiză Lexicală

  • • Uitarea stării curente în ε-closure: În orice calcul ε-closure(s), starea s însăși aparține întotdeauna mulțimii sale de închidere (distanța 0 tranziții ε)!
  • • Proprietatea Thompson: NFA-ul lui Thompson are întotdeauna exact o stare inițială și exact o stare finală, indiferent de complexitatea expresiei regulate.
  • • Efectul Maximal Munch pe identificatori ce conțin cuvinte cheie: Șirul while1 este întotdeauna returnat ca ID, NICIODATĂ ca WHILE urmat de cifra 1.
  • • Numărarea liniilor în Flex: Pentru ca variabila globală yylineno să funcționeze corect, în fișierul .l trebuie adăugată obligatoriu directiva %option yylineno.
